# 부모 계정 도입 설계안

상태: **제안 (미구현).** 사용자 방침(2026-10-22): 계정과 개인정보 처리는 **성인인 부모**를 대상으로 한다.
법률 판단은 이 문서에 없다. 개인정보 처리방침·동의 문구는 전문가 확인을 거친다.

## 1. 왜 필요한가 (지금의 한계)

| 문제 | 지금 | 계정이 있으면 |
|---|---|---|
| 기기를 바꾸거나 브라우저 데이터를 지우면 별·콜렉션·프로필이 사라짐 | 데이터가 기기 localStorage에만 있음 | 부모 계정에 저장되어 복구됨 |
| 부모 PIN을 아이가 재설정할 수 있음 | "PIN 잊음" = 계산 문제 하나 | 재설정을 **부모 이메일 링크**로 하게 되어 아이가 못 함 |
| 하루 사용 한도를 새 프로필로 피할 수 있음(PIN 있을 때만 막음) | 한도가 기기·프로필 단위 | 한도를 **계정 단위**로 서버에서 셈 |
| 요청 제한이 IP 기준이라 한 명이 전체 상한(300/일)을 소진할 수 있음 | IP별·전체 상한 | 계정별 상한 + 로그인한 사용자만 채팅 |
| 보호자 동의의 근거가 없음 | 동의 절차 없음 | 가입 때 부모가 동의하고 버전·시각이 기록됨 |

## 2. 추천안 (한눈에)

- **로그인:** 부모 **이메일 링크(비밀번호 없음)**. 이후 카카오 로그인 추가를 검토한다.
- **저장소:** **Supabase**(Auth + Postgres + 행 단위 보안). 이 세션에 Supabase 연동이 붙어 있어 프로젝트 생성·마이그레이션을 이어서 할 수 있다.
- **메일 발송:** Resend(연동 있음) 또는 Supabase 기본 메일. 무료 한도는 도입 전에 확인한다.
- **채팅 내용의 서버 저장:** **기본은 저장하지 않는다**(기기에만 둔다). 부모가 볼 "사용 현황"과 "안전 알림"만 서버에 둔다. (결정 필요: 아래 6번)
- **기존 데이터:** 첫 로그인 때 기기의 `banjjaktalk_v2` 데이터를 계정으로 한 번 가져온다. 저장 키는 바꾸지 않는다.

## 3. 데이터 모델 (초안)

```
parents        (id = auth.users.id, email, created_at, deleted_at)
consents       (parent_id, document, version, accepted_at)        -- 약관 / 개인정보 / 국외이전 고지
kids           (id, parent_id, name, birth_year, birth_month, avatar, interests, plan)
kid_state      (kid_id, rewards jsonb, decor jsonb, badges jsonb, stickers jsonb, updated_at)
settings       (parent_id, limit_per_day, pin_hash, pin_fails, pin_locked_until, voice, sound)
usage_daily    (kid_id, day, messages)                            -- 하루 한도를 서버가 셈
safety_events  (id, kid_id, at, category, activity_id, excerpt)    -- 부모 안전 알림용. 보관기간 짧게
```

- 모든 표는 `parent_id`로 **행 단위 보안(RLS)** 을 걸어 부모 본인 행만 읽고 쓰게 한다.
- `safety_events.excerpt`는 아이가 한 말의 일부라 가장 민감하다. 길이를 제한하고 보관기간(예: 90일)을 정한다.
- PIN은 해시로만 저장하고, 시도 횟수 제한을 서버가 한다.

## 4. 서버(`server.js`) 변경

1. `/api/chat`은 **로그인 토큰을 검증**하고, 계정 단위 일일 한도를 적용한다(IP 한도는 보조로 유지).
2. 한도·안전 이벤트는 서버가 기록한다. 클라이언트가 보내는 값을 믿지 않는다.
3. 환경변수 추가: Supabase URL, 서비스 키(서버 전용). **키는 대화나 저장소에 적지 않고 Render 대시보드에만 넣는다.**
4. `/api/health`에 데이터베이스 연결 상태를 추가한다(값은 노출하지 않음).

## 5. 단계별 계획

| 단계 | 내용 | 끝났다고 볼 기준 |
|---|---|---|
| 0 | 개인정보 처리방침·약관·국외이전 고지 초안, 결정 사항(6번) 확정 | 사용자 승인 |
| 1 | Supabase 프로젝트, 부모 가입(이메일 링크)·동의 화면·아이 프로필 동기화, 기기 데이터 가져오기 | 기기 교체 시 데이터 복구 테스트 통과 |
| 2 | 서버 검증(토큰), 계정 단위 한도, PIN 서버 검증·이메일 재설정 | 한도 우회·PIN 재설정 테스트 통과 |
| 3 | 안전 알림·사용 현황 서버 저장, 계정 삭제(모든 데이터 삭제) | 삭제 후 데이터가 남지 않는지 테스트 |
| 4 | (선택) 카카오 로그인, 채팅 내용 서버 저장 | 결정 후 |

각 단계마다 지금까지와 같이 테스트를 먼저 쓰고, 수정을 되돌리면 실패하는지 확인하고, 통과하면 `main`에 병합한다.

## 6. 사용자가 정해야 할 것

1. **로그인 방식:** 이메일 링크만 / 이메일 + 카카오. (추천: 이메일 링크로 시작)
2. **채팅 내용을 서버에 저장할지:** 저장하지 않음(추천) / 부모가 볼 수 있게 저장. 저장하면 개인정보 처리 부담과 유출 시 영향이 커진다.
3. **보관기간:** 안전 알림 발췌, 비활성 계정, 삭제 요청 처리 기한.
4. **가입 연령:** "만 19세 이상 보호자"로 한정할지(약관 문구와 확인 절차).
5. **법률 검토를 맡길 곳**과 처리방침 문구의 책임자.
6. **서비스 지역:** 서버·DB 위치(Oregon 등 해외)와 이에 대한 고지 방식.

## 7. 개인정보 고지에 들어가야 하는 것 (초안 목록, 법률 검토 필요)

- 수집 항목: 부모 이메일, 아이 이름·생년월·아바타·관심사, 사용 현황, (선택) 안전 알림 발췌
- 이용 목적: 서비스 제공, 사용 현황·안전 알림 제공, 하루 한도 적용
- **국외 이전·위탁:** 대화 내용이 AI 응답 생성을 위해 **Anthropic(미국)** 으로 전달된다. 호스팅(Render)·DB(Supabase)·메일 발송 업체의 위치와 역할도 적는다. 각 업체의 보관·학습 사용 정책은 도입 전에 **원문으로 확인**한다(이 문서는 확인하지 않았다).
- 보유·이용 기간, 삭제·정정·동의 철회 방법, 문의처

## 8. 위험과 대응

- **유출:** 저장 항목을 최소화하고(채팅 내용 미저장), RLS와 서비스 키 분리를 지킨다.
- **무료 플랜 한계:** Supabase·Render 무료 플랜의 정지·만료 정책을 도입 전에 확인한다. 아이 서비스가 멈추지 않도록 유료 전환 시점을 정한다.
- **로그인 장벽:** 가입이 번거로우면 이탈한다. 처음에는 계정 없이 쓰고 나중에 계정에 연결하는 흐름(기기 데이터 가져오기)을 유지한다.
- **구독:** 결제를 붙이면 결제 업체 선택·환불 정책이 추가된다. 이 설계안은 결제를 포함하지 않는다.
